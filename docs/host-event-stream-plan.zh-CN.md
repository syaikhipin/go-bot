# Host 统一事件流与会话内人工交互

状态：已实施并完成本地验证。

每个已连接的 Web / Mobile 客户端与当前账号的 Host 维护一条 SSE，经 Controller 透明转发。切换会话、进入设置、任务或文件系统不切换连接。消息、工具、队列、问题、审批依旧属于各会话；不提供全局审批弹窗，不自动跳转会话。

## 协议与职责

- `GET /v1/host/stream` 统一发送 `host` 事件，数据为 `{sessionId?, type, data}`。
- 会话事件保留既有公开投影及脱敏规则；`sessionId` 标识归属。Host 级 `sessions.changed`、`schedule/changed` 没有 `sessionId`。
- Host 直接订阅本地运行时，不为各会话建立内部 HTTP SSE。新激活的会话（包含定时任务创建的会话）自动加入。
- 历史通过现有 HTTP 分页读取。连接使用 `cursors` 携带已缓存会话的各自游标，补齐断线期间的事实；不新增跨会话日志或 Redis 消息队列。
- 初次连接、重连同步队列、执行权限、待处理问题及当前生成快照。未提供游标的会话与最近 20 轮历史重叠发送，前端按序号去重，覆盖会话创建到订阅就绪之间产生的消息。历史读取期间缓冲该会话到达的增量，读取完成后合并，避免丢消息。
- 尚未加载的会话只在前端内存保存生成中、待审批、待回答等摘要，首次打开再读取历史。已加载会话继续更新原有最多 20 个会话的缓存。摘要不是本地持久化文件，也不写 Redis。
- 会话列表显示轻量待处理标记。审批、方案审阅、问答仅在对应会话内展示；多个客户端中一个完成后，其他客户端同步撤下已处理项。
- 任务列表使用同一连接的变更通知刷新，不另建任务 SSE。移动端在前台保持连接，后台断开，回到前台重连。

## 人工交互

普通执行权限审批依照上游：不设置固定超时，等待允许一次、拒绝或调用取消。发起时无任何 Host 客户端且无其他交互处理方，返回 `unavailable`，不执行。已发起后客户端断线不取消；重连同步仍待处理项。取消 turn、停止 Host 会结束等待。不得由普通问答的补答路径放行权限。

`exit_plan_mode` 是方案审阅：复用问答表现，展示完整方案，允许按方案执行或输入意见继续规划，无固定超时，不提高执行权限。

`ask_user_question` 保留现有默认 120 秒等待、`timeout: -1`、超时后继续及补答消息机制。无客户端也可以发起；连接不会重置计时。
